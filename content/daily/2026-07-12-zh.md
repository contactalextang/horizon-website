## [1993 年 PDF 揭示 SVD 早期历史。](https://www.math.ucdavis.edu/~saito/courses/229A/stewart-svd.pdf) ⭐️ 8.0/10

hackernews · wolfi1 · Jul 11, 15:26 · [社区讨论](https://news.ycombinator.com/item?id=48872858)

**背景**: 奇异值分解（SVD）将任何实或复矩阵分解为三个矩阵，分别代表旋转、缩放和另一次旋转，对角线上的奇异值唯一确定。它将特征分解推广到矩形矩阵，是伪逆计算、低秩逼近和主成分分析等技术的基础。如今广泛使用的实用算法由 Gene Golub 和 Christian Reinsch 在 1970 年提出，建立在早期理论工作之上。

## [我们将 PgBouncer 的吞吐量提升了 4 倍](https://clickhouse.com/blog/pgbouncer-clickhouse-managed-postgres) ⭐️ 7.0/10

ClickHouse 博客描述了作者通过在多个 PgBouncer 实例之间使用对等（peering）并行运行，将 PgBouncer 的吞吐量提升了四倍，并详细说明了他们的方法和性能提升。 此扩展技术解决了 PgBouncer 单线程瓶颈，使得 PostgreSQL 工作负载能够在不升级硬件的情况下处理更高的并发连接，对云原生和 Kubernetes 部署尤为重要。 由于每个 PgBouncer 进程仅能使用一个 CPU 核心，团队在同一主机（或跨主机）上运行多个实例并启用对等机制，使取消消息能够转发给拥有会话的实例，从而实现约 4 倍的吞吐量提升。

hackernews · saisrirampur · Jul 11, 15:28 · [社区讨论](https://news.ycombinator.com/item?id=48872874)

**背景**: PgBouncer 是一个轻量级的 PostgreSQL 连接池器，通过复用数据库连接来降低开销，但它以单线程模式运行，导致其吞吐量受限于单个 CPU 核心，不管主机有多强大。要突破这一限制，运维人员可以运行多个 PgBouncer 实例并使用对等（peering）机制——即实例之间相互通信以转发与会话相关的消息，例如查询取消。这种方法常与 Kubernetes 等容器编排平台结合，以在多个节点上分发实例。

## [优先使用 SQLite 的严格表](https://evanhahn.com/prefer-strict-tables-in-sqlite/) ⭐️ 7.0/10

文章主张启用 SQLite 的 STRICT 表选项以强制列数据类型，并展示如何使用 sqlite-utils CLI 工具迁移现有表，该工具现已包含用于此目的的 transform 命令。 使用严格表可以提高数据完整性，防止类型不匹配，这在多个应用共享数据库时尤为重要。 严格表要求每列必须定义数据类型（INT、INTEGER、REAL、TEXT、BLOB 或 ANY），且不能就地修改；需要将数据复制到新的严格表。sqlite-utils 的 transform 命令可自动完成此转换，但严格模式不提供专门的 DATE 类型。

**背景**: SQLite 传统上使用动态类型，允许任何值存储在任何列中，不管声明的类型如何。严格表通过 STRICT 关键字引入，强制静态类型，拒绝无法转换为列声明类型的值。sqlite-utils 是一种流行的基于 Python 的 CLI 实用工具，用于检查、修改和查询 SQLite 数据库。
