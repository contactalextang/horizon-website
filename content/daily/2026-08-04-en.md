## [Rust project goals: Immobile types and guaranteed destructors](https://github.com/rust-lang/rust-project-goals/blob/main/src/2026/move-trait.md) ⭐️ 8.0/10

The Rust project goals announce plans to add immobile types (via a !Move trait) and guaranteed destructors (via a !Forget trait) to the language, aiming to eventually replace the Pin API. These features would enable safe self‑referential types and scoped task handling without unsafe Pin, improving safety and ergonomics for async and systems programming. The proposal introduces !Move to prohibit moving a type (enabling immobile, self‑referential structs) and !Forget to guarantee that a type’s destructor runs, preventing mem::forget from skipping cleanup; it notes that existing Rust code assumes all types are movable, so the change is significant and may affect future editions.

hackernews · paavohtl · Aug 3, 06:42 · [Discussion](https://news.ycombinator.com/item?id=49152023)

**Background**: Currently, Rust assumes every type can be moved freely and that destructors can be bypassed safely with std::mem::forget, which makes it impossible to guarantee cleanup for self‑referential types such as async futures. The Pin API was introduced as a workaround to pin values in place, but it relies on unsafe code and ergonomics are cumbersome. Immobile types and guaranteed destructors aim to provide a safe, language‑level alternative that eliminates the need for Pin.

## [AirLLM enables 70B LLM inference on a single 4GB GPU.](https://github.com/lyogavin/airllm) ⭐️ 7.0/10

AirLLM, a new open‑source library, allows a 70‑billion‑parameter language model to run on a single 4 GB GPU by swapping model layers in and out of VRAM during inference, without quantization or pruning. This technique dramatically lowers the hardware barrier for experimenting with very large LLMs, enabling researchers and hobbyists to test 70B models on consumer‑grade GPUs, though the extreme inference latency limits real‑world deployment. AirLLM performs layer‑by‑layer offloading, loading only the needed transformer layer into the 4 GB GPU at a time while keeping the rest on disk or system RAM, and reports inference speeds of hundreds of seconds per token on a 48 GB RTX 6000 Ada when running Kimi K3.

hackernews · Hacker News RSS · Aug 3, 11:15 · [Discussion](https://news.ycombinator.com/item?id=49154228)

**Background**: Large language models with tens of billions of parameters require hundreds of gigabytes of memory to store their weights, far exceeding the VRAM of most consumer GPUs. Techniques such as quantization, pruning, or model offloading aim to reduce this footprint, but often sacrifice accuracy or add complexity. AirLLM’s layer‑swapping approach keeps the full model on secondary storage and streams each layer into GPU memory only when needed for computation, preserving the original model’s precision.
