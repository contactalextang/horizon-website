## [Celld：自托管的分布式持久对象](https://github.com/denoland/celld) ⭐️ 8.0/10

Celld 是一个开源的、自托管的 Cloudflare 持久对象实现，使开发者能够使用 SQLite 和 S3 兼容存储运行有状态的复制边缘函数。 通过提供供应商无关的方式运行持久对象，Celld 减少了供应商锁定，使开发者能够在自己控制的任何基础设施上部署有状态的边缘应用。 每个持久对象作为独立的 SQLite 数据库运行，其状态会复制到 S3 兼容的存储桶，并且系统基于 Cloudflare Workers 运行时以支持 JavaScript 和 WASM。

hackernews · Hacker News RSS · Aug 5, 16:50 · [社区讨论](https://news.ycombinator.com/item?id=49185430)

**背景**: Durable Objects 是 Cloudflare 提供的有状态无状态服务原语，为每个对象提供独立的事务性存储，支持长连接、强一致性和自动扩展。边缘函数是部署在网络边缘的轻量级计算处理器，能够降低用户面向应用的延迟。Celld 通过让开发者在自己的机器上使用 SQLite 存储每个对象的状态并使用 S3 兼容存储进行复制，将这些概念带到任何环境。

## [文章探讨了 Webhook 的陷阱与解决方案。](https://weli.dev/blog/the-valley-of-webhooks/) ⭐️ 8.0/10

文章批评了 Webhook 在状态同步中的可靠性问题，并提出了一种类似 IETF 草案的订阅式协议 SCROLL 作为潜在解决方案。 指出 Webhook 的缺陷有助于开发者避免昂贵的一致性问题，而提出的标准化订阅机制可能提升 API 设计和跨服务状态同步的可靠性。 SCROLL 通过 GET 请求并携带 Prefer: stream 头来建立订阅，类似于 Braid‑HTTP Subscriptions 草案，并处理签名、去重、缓冲、引导和 cron 等问题，但需要持久连接，在低频事件时可能效率低下。

hackernews · Hacker News RSS · Aug 5, 15:22 · [社区讨论](https://news.ycombinator.com/item?id=49184216)

**背景**: Webhook 是一种 HTTP 回调，用于向外部系统通知事件，但可能出现延迟、乱序或重复投递，导致状态同步不可靠。状态同步的目标是保持分布式数据副本的一致性，通常需要可靠的投递和顺序。订阅式协议（如 IETF 草案 draft‑ietf‑netconf‑subscribed‑notifications）允许客户端通过单一连接请求定制的持续事件流。这些机制旨在相比传统 Webhook 提供更可靠、有序且可扩展的事件传递。
