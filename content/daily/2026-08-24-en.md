## [Achieving 5‑Microsecond JIT Compilation Latency](https://malisper.me/jit-compiling-code-in-5-us/) ⭐️ 8.0/10

The article shows how to achieve JIT compilation latency of just 5 µs by using LLVM’s ORC API with a CompileOnDemand layer, pre‑generated machine‑code stubs, and on‑stack replacement to swap interpreter frames for compiled code. Sub‑5‑microsecond JIT latency makes runtime code generation practically instantaneous, enabling dynamic languages and specialized workloads to approach the performance of ahead‑of‑time compiled code without noticeable warm‑up delays. The technique relies on LLVM ORC’s CompileOnDemand layer to defer compilation until first use, links a small set of pre‑relocated object files for fast code loading, and uses OSR to transfer execution state from the interpreter to the compiled version without stopping the program.

rss · Hacker News RSS · Aug 23, 06:04

**Background**: Just‑in‑time (JIT) compilation translates bytecode or intermediate representation to machine code at runtime, allowing programs to optimize based on actual execution patterns. On‑stack replacement (OSR) is a technique that lets a running method switch from interpreted to compiled execution mid‑loop by reconstructing the interpreter’s stack frame in the compiled code. LLVM’s ORC (On‑Request‑Compilation) framework provides modular layers such as CompileOnDemand and IRCompileLayer to build low‑latency JITs, while tiered compilation in the JVM uses a quick C1 compiler for startup and a slower C2 compiler for peak performance.
