## [RFC 10008 standardizes new HTTP QUERY method](https://www.rfc-editor.org/info/rfc10008/) ⭐️ 7.0/10

RFC 10008, published by the IETF, defines a new HTTP QUERY method that allows safe, idempotent requests with a request body, addressing the limitation of using GET with a body. The QUERY method fills a gap for APIs that need to send complex query parameters safely without side effects, benefiting GraphQL, REST, and form submissions by enabling cacheable, repeatable requests. QUERY requests are safe and idempotent, may include a request body, and the response can be cached when the server indicates so; the method also registers an Accept-Query header for negotiating response formats.

hackernews · Hacker News RSS · Jun 17, 10:51 · [Discussion](https://news.ycombinator.com/item?id=48568502)

**Background**: HTTP defines methods such as GET, POST, PUT, DELETE, where GET is intended for retrieving data and traditionally should not have a body; however, many APIs have used GET with a body to pass complex parameters, leading to interoperability and caching issues. The IETF HTTP Working Group explored allowing a body on GET but rejected it due to historical interoperability concerns, prompting the creation of a distinct QUERY method. RFC 10008 standardizes this method to provide a safe, idempotent alternative that can carry a payload.
