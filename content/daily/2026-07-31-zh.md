## [GitHub 在公开预览中推出堆叠拉取请求](https://github.blog/changelog/2026-07-30-stacked-pull-requests-are-now-in-public-preview/) ⭐️ 8.0/10

GitHub 已于 2026 年 7 月 30 日在公开预览中推出堆叠拉取请求（PR）功能，允许开发者将依赖的 PR 组织成堆栈并一次性合并。 此功能针对 AI 生成代码导致的巨大 PR 问题，使团队能够将大型更改拆分为小而易审的 PR，同时保持原子合并，从而提升代码审查效率并降低合并冲突。 堆叠 PR 原生集成在 GitHub 中，栈中的每个 PR 以栈的基础分支为目标，GitHub Actions 工作流可通过 github.event.pull_request.stack 获取栈元数据；虽然可以一次性合并整个栈，但若启用审查策略，每个 PR 仍需单独获得批准。

hackernews · Hacker News RSS · Jul 30, 16:26 · [社区讨论](https://news.ycombinator.com/item?id=49112232)

**背景**: 堆叠拉取请求是一系列依赖的 PR，每个 PR 基于前一个 PR 的分支，使得可以进行增量、聚焦的更改并独立审查。在原生支持之前，开发者只能依赖变通方案或第三方工具来管理这些依赖。GitHub 的内置实现现在提供了 UI、CLI 和 Actions 集成以支持此工作流。

## [扩展 PostgreSQL 作业队列并缓解 MVCC 膨胀的策略](https://www.dbos.dev/blog/making-postgres-queues-scale) ⭐️ 8.0/10

DBOS 博客文章概述了扩展基于 PostgreSQL 的作业队列的实际策略，重点在于缓解 MVCC 膨胀和调整 autovacuum 以适应高写入负载。 随着越来越多的应用依赖 PostgreSQL 进行作业处理，了解如何避免膨胀并保持 autovacuum 高效对于在不增加外部消息代理的情况下维持性能至关重要。 技术包括使用 SELECT … FOR UPDATE SKIP LOCKED 实现无锁的消费者工作器，调整 autovacuum_naptime 和 autovacuum_vacuum_cost_limit，分区或归档旧行，以及监控 pg_stat_user_tables 以观察死元组增长。

hackernews · Hacker News RSS · Jul 30, 18:39 · [社区讨论](https://news.ycombinator.com/item?id=49113913)

**背景**: PostgreSQL 的 MVCC 在每次 UPDATE 或 DELETE 时会创建新的元组版本，将旧版本留为死元组，除非被 VACUUM 清除否则会累积。自动清理（autovacuum）是一个后台进程，定期清理这些死元组，但其默认设置在高写入负载（如作业队列）下可能不足。FOR UPDATE SKIP LOCKED 子句允许多个工作器并发读取和锁定未被锁定的行，从而在数据库内部构建一个简单高效的队列。
