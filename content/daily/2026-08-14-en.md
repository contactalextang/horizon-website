## [Spaghettifying DRAM Exploit Reveals Low-Level Memory Access via Timing Manipulation](https://github.com/xoreaxeaxeax/skitter-creek-bath-salts) ⭐️ 8.0/10

A new exploit named 'Spaghettifying DRAM' demonstrates how flipping a single bit in the DRAM controller can rewire memory address translation, enabling access to protected CPU regions like the Platform Security Processor and System Management Mode. This technique bypasses all higher-level memory protections by exploiting low-level hardware behavior, revealing a significant and growing attack surface in modern memory systems that affects CPU security across vendors. The exploit was demonstrated on AMD Family 16h CPUs and uses linear algebra to reconstruct memory mappings; it requires ring-0 access and can expose hidden firmware and microcode by manipulating DRAM timing behaviors.

hackernews · Hacker News RSS · Aug 13, 14:17 · [Discussion](https://news.ycombinator.com/item?id=49286341)

**Background**: DRAM stores data in cells that require periodic refreshing and is vulnerable to timing-based attacks like Rowhammer, where repeated memory accesses cause bit flips in adjacent rows. Modern DRAM controllers include complex address translation and security features, but their increasing complexity introduces new vulnerabilities that can be exploited at the hardware level.

## [How Compaction Works in Pi for LLM Context Window Management](https://earendil.com/posts/compaction-in-pi/) ⭐️ 7.0/10

The article explains how compaction works in the Pi system to manage LLM context windows by summarizing and replacing old tokens during inference, using a dual KV cache strategy to maintain continuity. This technique helps developers working with local LLMs overcome context window limitations, enabling longer sessions without restarting, which is crucial for applications like coding agents and long-form reasoning. Compaction in Pi involves walking backward from the newest message to accumulate tokens until a keepRecentTokens threshold (default 20k) is reached, then summarizing the extracted segment and replacing it in the KV cache, which breaks prompt caching due to prefix mismatch.

hackernews · Hacker News RSS · Aug 13, 17:57 · [Discussion](https://news.ycombinator.com/item?id=49289654)

**Background**: Large language models have a fixed context window measured in tokens, beyond which older inputs are forgotten or truncated. To manage this, techniques like compaction summarize and replace older parts of the context to free space for new input. The KV cache stores key and value states from previous tokens to avoid recomputation during autoregressive generation, but its size grows linearly with context length, creating memory bottlenecks.

## [Single log line triggers excessive disk writes in systemd-journald](https://github.com/systemd/systemd/issues/40262) ⭐️ 7.0/10

A single log line in systemd-journald causes disproportionately large disk writes — 49KB+ on ext4 and 110KB+ on btrfs — due to inefficient journaling behavior, as reported in GitHub issue #40262. This highlights a critical performance flaw in systemd-journald that can severely impact SSD lifespan and system responsiveness, especially under high-log-volume scenarios like driver faults, affecting Linux administrators and embedded systems relying on persistent logging. The excessive writes stem from journald's design of appending log data with frequent metadata updates in the header to maintain atomicity and mmap()-based access, causing write amplification even for minimal log entries, particularly noticeable on copy-on-write filesystems like btrfs.

hackernews · Hacker News RSS · Aug 13, 18:41 · [Discussion](https://news.ycombinator.com/item?id=49290215)

**Background**: systemd-journald is the default logging service in most modern Linux distributions, storing logs in a binary, indexed format designed for robustness and fast querying. Unlike traditional text logs, it uses a journal file format inspired by append-only designs like Git, where new entries are added at the end and metadata is updated to maintain consistency, which can lead to inefficient disk usage when handling high-frequency, low-volume logging events.
