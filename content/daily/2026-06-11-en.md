## [HelixDB: Open-source OLTP graph DB on object storage with vector & full-text search](https://github.com/HelixDB/helix-db/tree/main) ⭐️ 8.0/10

HelixDB is an open-source OLTP graph database built on object storage that natively integrates vector search and full-text search, released over a year ago by its creators as a college project and now available on GitHub. By combining graph, vector, and full-text search in a single system built on cheap object storage, HelixDB eliminates the complexity of joining disparate databases for AI-driven workloads, offering scalable, low-latency access to massive datasets while reducing operational costs. HelixDB is implemented in Rust, stores graph and vector data in object storage (e.g., S3), achieves ~100ms p99 write and ~50ms p99 read latency from cold storage, and scales horizontally by caching hot subgraphs on nodes while offering upcoming pre‑filtering for vector search and a managed GA cloud.

hackernews · Hacker News RSS · Jun 10, 15:47 · [Discussion](https://news.ycombinator.com/item?id=48478148)

**Background**: OLTP (Online Transaction Processing) graph databases are designed for fast, transactional reads and writes on interconnected data represented as nodes and edges. Object storage services such as Amazon S3 provide virtually unlimited, low‑cost durability for large binary objects, making them suitable for persisting massive graphs that exceed memory limits. Combining native vector search (for semantic similarity) and full‑text search with a graph model allows AI applications to traverse relationships, retrieve semantically related entities, and filter by text without moving data between separate systems.

Recent work such as Gemini Diffusion explored this paradigm for language, showing that diffusion can approach autoregressive quality while offering computational advantages.
