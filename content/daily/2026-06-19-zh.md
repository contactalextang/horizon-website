## [Z.ai 发布 GLM-5.2，一个具有 1M-token 上下文的 753B 参数 MoE 开放权重 LLM](https://simonwillison.net/2026/Jun/17/glm-52/#atom-everything) ⭐️ 9.0/10

6 月 13 日，Z.ai 向编码计划订阅者发布了 GLM-5.2，并于 6 月 16 日在 MIT 许可证下公开发布了完整模型权重。该模型是一个 7530 亿参数的 Mixture‑of‑Experts（MoE）纯文本 LLM，约有 400 亿活跃参数，上下文窗口为 100 万 token。 GLM-5.2 在 Artificial Analysis Intelligence Index v4.1 上以 51 分领先，超越 MiniMax‑M3、DeepSeek V4 Pro 等开放模型，并在 Code Arena WebDev 排行榜上位列第二。其 MIT 许可的开放权重和 100 万 token 上下文使其能够支持长时程编码和智能体工作流，且不受专有限制。 尽管规模巨大，GLM-5.2 在每个 Intelligence Index 任务上大约消耗 43k 输出 token，高于其他开放模型，且在 OpenRouter 上的定价约为每百万输入 token 1.40 美元、每百万输出 token 4.40 美元。模型能够生成完整的动画 SVG（如骑自行车的鹈鹕），但在更复杂的提示（如 opossum 在电动滑板车上）上表现不佳。

rss · Simon Willison · Jun 17, 23:58

**背景**: 专家混合（MoE）架构通过将每个 token 路由到一组专家网络子集来工作，使得 GLM‑5.2 这类模型能够拥有数千亿参数而在推理时仅激活一小部分（约 400 亿）。100 万 token 的上下文窗口使模型能够一次性处理极长的输入，例如整个代码库或长文档，这在最近的 LLM 上下文窗口综述中得到强调。以 MIT 许可证发布完整权重消除了使用限制，允许无限制的微调、商业部署以及社区驱动的创新。

文章介绍了几种超越标准 .gitignore 的 Git 忽略文件机制，包括 .gitattributes、通过 core.excludesFile 设置的全局排除以及使用 git update‑index 设置的 assume‑unchanged 标志，并突出了 Hacker News 社区分享的实用技巧。 了解这些替代方案能让开发者保持仓库范围的 .gitignore 干净，避免提交个人 IDE 或操作系统文件，并在所有项目中统一应用忽略规则，而无需逐个修改仓库。 .gitattributes 可以通过 export‑ignore 或 diff 属性来在归档或 diff 中抑制文件更改；全局排除通过 git config --global core.excludesFile 指向如 ~/.config/git/ignore 的文件进行配置；assume‑unchanged 使用 git update-index --assume-unchanged 对单个文件设置（用 --no-assume-unchanged 清除），而 skip‑worktree 提供类似但更可靠的替代方案。
