## [Project Valhalla 的值类特性将在 JDK 28 中发布，历时十年](https://www.jvm-weekly.com/p/project-valhalla-explained-how-a) ⭐️ 9.0/10

文章详细说明了 Project Valhalla 如何将值类及相关特性引入 JDK 28，标志着超过十年的开发工作终于完成。 值类使得对象能够以紧凑的方式存储，消除每个对象的头部开销，并提供 null‑安全，这将大幅提升数据密集型 Java 应用的性能。 值类没有对象身份，使得 JVM 能够直接在数组中存放它们的字段（例如，一个包含两个 32 位整数的 Point 占用 8 字节加上可选的 null 标志），但若超过 64 位则失去内联存储的优势。

hackernews · philonoist · Jun 19, 06:35 · [社区讨论](https://news.ycombinator.com/item?id=48595511)

**背景**: Project Valhalla 是一个长期进行的 OpenJDK 倡议，旨在将值类型引入 Java 类型系统，以将对象的抽象与原始类型的性能结合。值类（也称为内联类）没有对象身份，使得 JVM 能够直接在数组中存放它们的字段，从而消除每个对象的头部开销和垃圾回收开销。JDK 28 将是首个包含这些值类特性的版本，经过了多年的早期访问构建和社区反馈。

## [ATProto 中没有实例](https://overreacted.io/there-are-no-instances-in-atproto/) ⭐️ 8.0/10

文章澄清 ATProto 不采用 Mastodon 所使用的“实例”概念，纠正了关于其架构的常见误解。 理解这一区别有助于开发者和用户把握 ATProto 与基于 ActivityPub 的系统之间的差异，为构建或选择去中心化社交平台提供参考。 ATProto 将用户数据存储在个人数据服务器（PDS）中，通过中继（Relay）聚合和分发数据流，AppView 消费这些数据流；没有实例或联邦服务器的概念。

hackernews · danabramov · Jun 19, 15:10 · [社区讨论](https://news.ycombinator.com/item?id=48599515)

**背景**: ATProto（Authenticated Transfer Protocol）是一种用于去中心化发布的开放标准，用户将 JSON 记录写入自己的个人数据服务器（PDS），而中继（Relay）聚合这些记录供应用（AppView）消费。与 Mastodon 不同，Mastodon 依赖称为“实例”的独立服务器，每个服务器托管网络数据的完整副本；ATProto 将存储、分发和应用层分离，因而不需要实例。该设计借鉴了网络模型：独立站点发布数据，索引器创建视图，而不是 ActivityPub 类似电子邮件的联邦模型。
