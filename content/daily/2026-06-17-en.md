## [Stop Using JWTs for Browser Sessions, Hacker News Debate](https://gist.github.com/samsch/0d1f3d3b4745d778f78b230cf6061452) ⭐️ 7.0/10

A Hacker News post titled “Stop Using JWTs” (gist.github.com/samsch/0d1f3d3b4745d778f78b230cf6061452) generated 169 points and 106 comments arguing that JWTs are unsuitable for browser‑based user sessions while still being useful for service‑to‑service communication. The debate highlights persistent security and operational concerns with JWTs, especially regarding token revocation and theft, influencing how developers choose authentication mechanisms for web apps. JWTs are signed, stateless tokens that carry an expiry; revocation typically requires a blacklist or very short lifetimes, and commenters noted that short expiry keeps revocation lists small, while service‑to‑service uses benefit from signed assertions without needing immediate revocation.

hackernews · Hacker News RSS · Jun 16, 16:49 · [Discussion](https://news.ycombinator.com/item?id=48558147)

**Background**: JSON Web Tokens (JWT) are compact, URL‑safe JSON objects used to transmit claims between parties, commonly employed for stateless authentication and authorization in web applications【https://www.geeksforgeeks.org/web-tech/json-web-token-jwt/】. Because they are stateless, revoking a JWT is not straightforward; strategies include maintaining a blacklist of revoked token IDs, using very short access token lifetimes with refresh tokens, or combining both approaches【https://supertokens.com/blog/revoking-access-with-a-jwt-blacklist】. In browser‑based sessions, tokens are stored client‑side and vulnerable to theft, whereas service‑to‑service authentication often relies on JWTs as trusted assertions between backend services where immediate revocation is less critical【https://www.loginradius.com/blog/identity/token-based-authentication-vs-session-authentication】.
