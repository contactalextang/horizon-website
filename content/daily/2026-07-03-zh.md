## [Linux 6.9 LUKS 挂起回归导致加密密钥残留内存](https://mathstodon.xyz/@iblech/116769502749142438) ⭐️ 8.0/10

自 Linux 内核 6.9 起，LUKS 挂起功能在挂起到 RAM 时不再清除磁盘加密密钥，导致密钥可能泄露。 该问题源于内核挂起处理的变更，遗漏了擦除 LUKS 主密钥的调用，这一错误在 Linux 6.9 开发周期中被发现，目前已有修复补丁提出。

hackernews · Hacker News RSS · Jul 2, 15:25 · [社区讨论](https://news.ycombinator.com/item?id=48763035)

**背景**: LUKS（Linux Unified Key Setup）是 Linux 标准的磁盘加密层，在系统运行时将主密钥保存在内核内存中。在挂起到 RAM（睡眠）期间，内核通常会擦除此密钥以防止 RAM 被读取时泄露。自 Linux 6.9 起，这一擦除步骤被意外移除，导致密钥在系统恢复或断电前仍驻留内存。

## [Podman 6.0.0 发布，带来增强网络、Quadlet 功能及自动 SQLite 迁移。](https://blog.podman.io/2026/07/introducing-podman-v6-0-0/) ⭐️ 8.0/10

Podman v6.0.0 引入了基于 Netavark、Pasta 和 nftables 的现代化网络，增强了 Quadlet 功能（新增 podman quadlet list 和 podman system migrate --migrate-db 命令），并自动将 BoltDB 后端迁移到 SQLite 以提升性能和可靠性。 此版本解决了 Podman 网络栈和存储后端的长期限制，使其更适合生产工作负载，并降低从 Docker 迁移的门槛。这些改进还使 Podman 与现代 Linux 容器工具趋势保持一致，如基于 nftables 的网络和基于 SQLite 的元数据存储。 网络改造用 Netavark、Pasta 和 nftables 替换了 slirp4netns 和 iptables；Quadlet 新增 list 命令和手动迁移标志，而 6.0.0 版本在启动时自动执行 podman system migrate --migrate-db 将 BoltDB 转换为 SQLite，仍在使用 BoltDB 的系统需先升级到 5.8。

hackernews · Hacker News RSS · Jul 2, 14:23 · [社区讨论](https://news.ycombinator.com/item?id=48762098)

**背景**: Podman 是一种无守护进程的容器引擎，使用 libpod 库管理容器、pod 和镜像，提供与 Docker 兼容的 CLI 并默认以 rootless 方式运行。Quadlet 是 Podman 的一项功能，允许用户用简单的 .container、.volume 和 .network 文件声明容器、卷和网络，这些文件会被自动转换为 systemd 服务单元以便管理。过去，Podman 使用 BoltDB 键值存储保存内部元数据，并依赖 slirp4netns 和 iptables 进行网络通信，但随着工作负载的增加，这两者都显示出可扩展性限制。Podman 6.0.0 向 SQLite 和 Netavark/Pasta/nftables 的迁移解决了这些限制，提供了更好的并发访问、崩溃恢复以及面向未来的网络。

## [PostgreSQL 事务为分布式工作流提供原子性。](https://www.dbos.dev/blog/co-locating-workflow-state-with-your-data) ⭐️ 8.0/10

2026 年 6 月 15 日，DBOS 发布博客展示如何将工作流状态与应用数据放在同一个 PostgreSQL 事务中，以实现分布式步骤的原子性，从而免除单独的 outbox 表。 该技术为开发者提供了跨服务边界的 ACID 保证，简化了可靠的事件驱动架构，并减少了分布式事务的样板代码。 它使用 PostgreSQL 用户定义函数在更新业务数据的同一事务中入队工作流步骤，确保两者要么都成功要么都回滚；该方法依赖于 PostgreSQL 的 MVCC 和隔离级别，但将工作流逻辑紧密耦合到数据库，可能影响可扩展性。

hackernews · Hacker News RSS · Jul 2, 18:38 · [社区讨论](https://news.ycombinator.com/item?id=48765639)

**背景**: PostgreSQL 事务保证 ACID 特性，确保一组操作要么全部提交要么全部回滚。outbox 模式将消息存储在与业务数据同一事务中的表里，以实现可靠的消息传递而无需单独的消息队列。通过将工作流状态（如步骤计数器或状态）与应用数据 colocated 在 PostgreSQL 中，工作流的进度成为事务的一部分，从而在分布式步骤之间实现原子性。这种方法避免了两阶段提交的复杂性，同时仍提供强一致性。
