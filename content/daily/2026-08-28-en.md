## [Cloudflare cuts 100 TB memory use in 1.1.1.1 DNS cache via Rust optimizations.](https://blog.cloudflare.com/dns-cache-memory-optimization-1111/) ⭐️ 8.0/10

Cloudflare announced five Rust-level memory optimizations to the DNS cache layout of its Big Pineapple platform, reducing per‑entry memory by 56% and freeing roughly 100 terabytes of RAM across its fleet. The optimization shows how low‑level data‑structure improvements can yield massive savings at scale, benefiting a widely used public DNS resolver and demonstrating the value of systems programming in cloud infrastructure. The changes included better struct packing, eliminating separate allocations for record data, using slab‑like allocation, and reducing metadata overhead, which together cut the per‑entry footprint from about 180 bytes to about 80 bytes.

hackernews · r/programming · Hacker News RSS · Aug 27, 17:17 · [Discussion](https://news.ycombinator.com/item?id=49468083)

**Background**: DNS caching stores recent domain‑to‑IP mappings to speed up lookups and reduce load on authoritative servers. Cloudflare’s 1.1.1.1 resolver, powered by the Big Pineapple platform, handles over 250 billion cache entries, so even a few bytes saved per entry translate to terabytes of RAM. Slab allocation is a kernel memory technique that reduces fragmentation by allocating objects from pre‑allocated caches, a strategy Cloudflare adapted for its DNS cache entries.
