## [Using a moving train as a linear slit‑scan scanner](https://philo.gay/linecam/) ⭐️ 8.0/10

The setup uses a standard webcam or similar sensor, capturing a narrow vertical slice about 15 pixels wide as the train passes, then stitches the slices together to form the final image; results depend on train speed, lighting, and a steady frame rate.

**Background**: Slit‑scan photography places a slit between the camera and subject during a long exposure, producing images that are stretched, abstracted, or distorted; it has been used for finish‑line photos and panoramic imaging. A moving train acts as a continuous linear scanner, where each column of the image corresponds to a moment in time as the train rolls past, similar to the rolling‑shutter effect found in many CMOS sensors. Earlier experiments include Ward Cunningham’s 2008 setup with an iSight camera and patents for train‑shape scanning using line‑scan cameras.

## [Linux 7.3 improves performance when GPU memory runs out.](https://pixelcluster.dev/VRAM-Overcommit/) ⭐️ 8.0/10

Linux kernel version 7.3 includes new patches that improve VRAM overcommit handling, reducing the performance drop when graphics memory is exhausted. These changes make graphics‑intensive applications more stable and responsive. As gaming, AI workloads and professional graphics apps often exceed physical VRAM, better kernel‑level overcommit reduces stalls and improves user experience without requiring hardware upgrades. The improvement also benefits developers who rely on predictable GPU memory behavior. The patches enable the kernel driver to coordinate with applications about memory “stickiness” and to mitigate slowdown when VRAM pages are evicted to system RAM, while also addressing virtual memory fragmentation. They have been merged upstream and are slated for inclusion in the Linux 7.3 release.

hackernews · Hacker News RSS · Aug 18, 07:51 · [Discussion](https://news.ycombinator.com/item?id=49342719)

**Background**: VRAM (video RAM) is the dedicated memory on a GPU used for textures, frame buffers and compute data. When applications allocate more VRAM than physically available, the system can overcommit, moving excess pages to system RAM, which is much slower and can cause noticeable performance drops. Linux kernel 7.3 introduces mechanisms to make this overcommit process more efficient, reducing the impact on graphics‑intensive workloads.

## [Turbovec: Rust Implementation of Google's TurboQuant for Vector Search](https://github.com/RyanCodrai/turbovec) ⭐️ 7.0/10

Turbovec is a newly released Rust library that implements Google's TurboQuant quantization technique for efficient approximate nearest neighbor vector search, aiming to reduce memory usage while maintaining search quality. By bringing TurboQuant to Rust, Turbovec enables memory‑constrained environments such as edge devices and WASM targets to run high‑performance vector search without the heavy footprint of traditional indexes like FAISS. The implementation supports configurable bit‑width quantization (e.g., 3‑bit), offers low memory footprint (~4 GB for 10 million vectors), and can be compiled to WASM or used with SQLite bindings for embedded use.

hackernews · Hacker News RSS · Aug 18, 18:07 · [Discussion](https://news.ycombinator.com/item?id=49349898)

**Background**: TurboQuant is an online vector quantization algorithm introduced in 2025 that compresses high‑dimensional Euclidean vectors while preserving their geometric structure and achieving near‑optimal distortion rates. Approximate nearest neighbor (ANN) search enables fast similarity retrieval in large vector datasets by trading a small amount of accuracy for significant speed gains, using indexing methods such as IVF, HNSW, and product quantization. Turbovec applies TurboQuant to ANN search, allowing vectors to be stored in a compact quantized form and searched efficiently without exhaustive comparison.
