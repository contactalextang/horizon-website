## [“意大利面化 DRAM”漏洞揭示通过时序操纵实现低级内存访问](https://github.com/xoreaxeaxeax/skitter-creek-bath-salts) ⭐️ 8.0/10

一种名为“意大利面化 DRAM”的新型漏洞表明，通过在 DRAM 控制器中翻转单个比特，可以重新布线内存地址转换，从而访问受保护的 CPU 区域，如平台安全处理器和系统管理模式。 此技术通过利用底层硬件行为绕过所有更高级别的内存保护，揭示了现代内存系统中日益增长的重大攻击面，影响各厂商的 CPU 安全。 该漏洞在 AMD Family 16h CPU 上演示，利用线性代数重建内存映射；它需要 ring-0 访问权限，并可通过操纵 DRAM 时序行为暴露隐藏的固件和微码。

hackernews · Hacker News RSS · Aug 13, 14:17 · [社区讨论](https://news.ycombinator.com/item?id=49286341)

**背景**: DRAM 将数据存储在需要定期刷新的单元格中，容易受到基于时序的攻击，如 Rowhammer，其中重复的内存访问会导致相邻行发生位翻转。现代 DRAM 控制器包含复杂的地址转换和安全特性，但其日益增加的复杂性引入了新的漏洞，这些漏洞可在硬件层面被利用。

## [Pi 系统中压缩如何工作以管理 LLM 上下文窗口](https://earendil.com/posts/compaction-in-pi/) ⭐️ 7.0/10

文章解释了 Pi 系统如何通过在推理过程中总结和替换旧令牌来管理 LLM 上下文窗口的压缩机制，并使用双 KV 缓存策略保持连续性。 此技术帮助使用本地 LLM 的开发者克服上下文窗口限制，无需重启即可实现更长的会话，这对于编码代理和长篇推理等应用至关重要。 Pi 中的压缩过程涉及从最新消息开始向后遍历，累积令牌直到达到 keepRecentTokens 阈值（默认 20k），然后总结提取的片段并替换到 KV 缓存中，由于前缀不匹配而破坏提示缓存。

hackernews · Hacker News RSS · Aug 13, 17:57 · [社区讨论](https://news.ycombinator.com/item?id=49289654)

**背景**: 大型语言模型具有固定的上下文窗口（以令牌为单位），超过此限制时，较旧的输入会被遗忘或截断。为了管理这一点，诸如压缩之类的技术会总结并替换上下文的较旧部分，以腾出空间容纳新输入。KV 缓存存储来自之前令牌的键和值状态，以避免在自回归生成过程中重复计算，但其大小会随着上下文长度线性增长，从而造成内存瓶颈。

## [单行日志导致 systemd-journald 产生过度磁盘写入](https://github.com/systemd/systemd/issues/40262) ⭐️ 7.0/10

systemd-journald 中的一行日志会导致不成比例的大量磁盘写入 —  — 在 ext4 上为 49KB+，在 btrfs 上为 110KB+，这是由于日志记录行为低效造成的，如 GitHub issue #40262 所示。 这凸显了 systemd-journald 中一个关键的性能缺陷，可能严重影响 SSD 寿命和系统响应性，特别是在驱动故障等高日志量场景下，影响依赖持久化日志的 Linux 管理员和嵌入式系统。 过度写入源于 journald 的设计：为了保持原子性和基于 mmap() 的访问，它会频繁在头部更新元数据以追加日志数据，即使是极少的日志条目也会导致写入放大，尤其在 btrfs 等写时复制文件系统上更为明显。

hackernews · Hacker News RSS · Aug 13, 18:41 · [社区讨论](https://news.ycombinator.com/item?id=49290215)

**背景**: systemd-journald 是大多数现代 Linux 发行版的默认日志服务，以二进制、索引化的格式存储日志，旨在提供鲁棒性和快速查询。与传统文本日志不同，它采用类似 Git 的追加-only 日志文件格式：新条目添加到末尾，同时更新元数据以保持一致性，但在处理高频、低容量的日志事件时，这可能导致磁盘使用效率低下。
