## [EU Proposes Hardware-Bound Attestation for Online Age Verification](https://linuxiac.com/eu-age-verification-project-mandates-hardware-bound-attestation/) ⭐️ 8.0/10

The European Commission is drafting rules that would require online age‑verification systems to use hardware‑bound attestation, tying proof of age to device‑specific keys such as TPM, Secure Enclave or Android Keymaster. The move could reshape digital privacy and competition by forcing users to rely on a limited set of vendor‑controlled hardware roots, raising concerns about surveillance, digital sovereignty and anti‑competitive lock‑in. Hardware‑bound attestation generates a private key inside a trusted execution environment (e.g., TPM 2.0, Apple Secure Enclave, Android Keymaster) and signs an attestation statement that includes a chain of vendor‑issued certificates proving the key originated on genuine hardware.

hackernews · Hacker News RSS · Aug 2, 20:44 · [Discussion](https://news.ycombinator.com/item?id=49148128)

**Background**: The EU Age Verification project aims to let users prove they are over 18 to access adult‑restricted content such as pornography, gambling and alcohol purchases online. Hardware‑bound attestation, as defined by standards like ACME Device Attestation and Android Keystore attestation, creates a device‑specific key rooted in a hardware trust module that cannot be exported. This approach ensures the attestation is tied to the physical device but also exposes a stable hardware identifier unless privacy‑enhancing techniques are used.

## [F* is a proof-oriented language for verified software](https://fstar-lang.org/) ⭐️ 7.0/10

F* is introduced as a general-purpose, proof-oriented programming language that supports dependent types, monadic effects, and refinement types to express high-assurance properties. It can be compiled to OCaml, F#, C, WebAssembly, or assembly for execution. By enabling programmers to write code alongside machine-checkable proofs, F* helps eliminate critical bugs and security vulnerabilities in software that requires high assurance, such as cryptographic protocols and operating system components. Its adoption can improve trust in safety-critical systems across industry and academia. F*'s type system combines dependent types, monadic effects, and refinement types, and its checker uses SMT solving plus interactive proofs to verify specifications. Programs can be extracted to OCaml, F#, C, WebAssembly (via KaRaMeL) or assembly (via Vale), and the language has been under active development since its 2011 inception by Microsoft Research and Inria.

hackernews · Hacker News RSS · Aug 2, 12:31 · [Discussion](https://news.ycombinator.com/item?id=49143925)

**Background**: Proof-oriented programming is a paradigm where developers write both code and formal mathematical proofs to guarantee correctness and security properties. Dependent types allow types to depend on values, enabling precise specifications such as arrays whose length is part of their type. F* leverages these features to express functional correctness, security, and other high-assurance properties that can be automatically checked by an SMT solver or manually proven.
